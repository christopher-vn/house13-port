# 三更灵异事件 — «Дом №13»: исследование и порт

Приватный репозиторий проекта по реверс-инжинирингу и портированию J2ME-игры
**三更灵异事件** (Sāngēng Língyì Shìjiàn — «Паранормальные явления третьей стражи»),
китайской хоррор-квест-бродилки для мобильных телефонов 2008 года.

## Об игре

| | |
|---|---|
| Оригинал | 三更灵异事件 (Sangen Lingyi Shijian) |
| Разработчик | 北京无限乐游科技有限公司 (Beijing Wuxian Leyou), Пекин, 2008 |
| Жанр | 2D хоррор-квест / point-and-click-бродилка, экранная навигация по комнатам |
| CN-версия | Motorola E398, 176×208; единственный билд (JAR с jvgm.cc, см. вывод №6); код не обфусцирован |
| RU-версия | «Дом №13», неофициальный перевод V.P.K (2008); SonyEricsson K700, 240×320; код обфусцирован, коллизии переписаны, перевод вольный (изменён сюжет) |

Русское название «Дом №13» — выдумка локализаторов (из их же предыстории про пятницу 13-е).
Правильный перевод названия — «Паранормальные явления третьей стражи»: 三更 — «третья стража»
(около 23:00–01:00, «часа полуночи» в китайской традиции).

## Ключевые выводы исследования

Полный отчёт: `docs/Дом_№13_отчёт_об_исследовании.docx`. Кратко:

1. **RU-версия построена из CN-кода** (идентичные баги, в т.ч. выход за границы `toolStates[31]`; мёртвый код), но существенно доработана: разрешение 240×320, Nokia FullCanvas, и главное — **движение руки-курсора переписано с нуля**: ~1300 строк хардкода `drawHand()` заменены на 18 массивов прямоугольников-стен + универсальный цикл коллизий.
2. Граф комнат (18 комнат), все пазлы, сейф (код 9819), инвентарь — полностью идентичны.
3. Сохранений нет ни в одной версии (нет RMS). Музыка: в JAR реально только 2 MIDI (menu, mapbg), SFX отсутствуют.
4. Кириллица в RU решена системным шрифтом `Font.getFont(0,0,8)` — битмап-шрифтов нет.
5. Китайские титул и «нажми любую клавишу» так и не переведены даже в RU-версии (LOGO1.png, logore.png).
6. **JAR с jvgm.cc = тот же единственный CN-билд E398**, с которого снята декомпиляция
   (наборы файлов совпадают 1-в-1). «240×320» в листинге jvgm — ошибка портала: билда
   240×320 не существовало, **всю работу 240×320 (фоны back1-15, FullCanvas, коллизии)
   сделали русские локализаторы**. CFR-декомпиляция JAR подтвердила эталонность имеющейся
   декомпиляции (374 члена класса, те же константы: сейф 9819, sleep(100)). Даты в JAR:
   старейшие файлы — оба MIDI (2005-08-04, заимствованы), финальная сборка 2008-02-20.

Словарь соответствия методов и полей CN↔RU — в worklog (`docs/worklog.md`, задача 2-code-diff):
он нужен для портирования, т.к. RU-код читаем только через «розеттский камень» CN-версии.

## Архитектурные решения (обновлено 2026-10-14: выбран Java + libGDX)

- **Язык/платформа**: Java + libGDX (Gradle). Оригинал — Java (J2ME), поэтому порт —
  по сути транскрипция API: `Canvas`→`Screen`/`render()`, `Image`→`Texture`,
  blit+текст → `SpriteBatch`+`BitmapFont`. **JNI не требуется**: игра простая, ввод,
  аудио и графика полностью покрываются libGDX. Модули: `core/` (вся логика),
  `lwjgl3/` (десктоп), `android/` (этап 6). Код — Java 8-совместимый, сборка JDK 17.
- **Ассеты не апскейлятся** (решение зафиксировано). Рендер в логическом разрешении
  **240×320** + целочисленный масштаб в окно (nearest): ×2=480×640 … ×7=1680×2240
  (влезает в телефон 1080×2340 — почти весь экран). В libGDX: `TextureFilter.Nearest`
  + собственный `IntegerScaleViewport` (целочисленный `FitViewport`).
- **Цикл**: логика — фиксированный шаг 100 мс (10 Гц, как в оригинале: скорость руки
  50 px/с и все тайминги сохраняются), рендер — по vsync.
- **Аудио**: канонические исходники — MIDI (`menu.mid`, `mapbg.mid`, оба 2005 года);
  в сборку пререндерятся в OGG/WAV через SoundFont пользователя (.sf2 в репо не входит —
  размер/лицензии). В рантайме — только аудио libGDX; `javax.sound.midi` не используем:
  на Android его нет вообще, пререндер даёт одинаковый звук на всех платформах.
- **База логики**: RU `b.java` — координаты 240×320 (массивы коллизий `f()`/`p()`,
  hot-zones `try(int)`); читаемость — через словарь CN↔RU из worklog.
- **База ассетов**: RU 240×320 (back1-15, LOGO, меню, toolback); 63 спрайта предметов
  и MIDI идентичны во всех сборках — берутся как есть. EXTD-апскейлы не используются.

## Дорожная карта

- [ ] 0. Аудио: пререндер menu.mid/mapbg.mid → OGG (fluidsynth + SoundFont пользователя); проверить gapless-луп на Android
- [ ] 1. Каркас libGDX: `core`+`lwjgl3`, `IntegerScaleViewport`, фикс. шаг 10 Гц, загрузка RU-ассетов
- [ ] 2. «Первый свет»: back1.png + спрайт руки + коллизии (`f()`/`p()` из RU b.java)
- [ ] 3. Машина состояний (лого → меню → игра → пауза), ввод (маппинг клавиш J2ME → libGDX)
- [ ] 4. Комнаты 1–18, инвентарь, пазлы, сейф 9819 (по словарю соответствия из worklog)
- [ ] 5. Вычитанный перевод CN→RU; шрифты FreeType (кириллица + CJK для опции языка)
- [ ] 6. Android-модуль: gradle + NDK-обвязки libGDX, тач-ввод

## Примечания

- `reference/House13CN_DECOMP/back1(EXTD).png` (704×832) и `back1(EXTD+).png` (1408×1664) —
  **эксперименты пользователя с AI-апскейлом** (×4 и ×8 от CN-фона 176×208), сделаны при
  планировании переноса в GameMaker. **Не игровые ассеты**, кодом не используются,
  при портировании не задействуются.
- Массивы коллизий для порта брать из RU `b.java` (методы `f()` + `p()`) —
  они же выверены против CN-хардкода `drawHand()`.
- `reference/jvgm-e398/9824413358.jar` — оригинальный билд, полученный пользователем
  с jvgm.cc (требовалась регистрация по китайскому номеру, помог знакомый). Именно он
  послужил источником `House13CN_DECOMP`; md5-сверка ассетов и CFR-декомпиляция
  подтверждают эквивалентность.
