# Геймпад — фундамент (этап 5e)

Состояние: **фундамент заложен** — архитектура, маппинг, тесты, рабочий
десктопный мост. «Полная реализация» (оверлей, ремап, вибрация, Android)
соберётся поверх без переделок. Дата: 2026-10-15.

## Архитектура в одном абзаце

Геймпад встраивается в существующую трубу ввода КАК КЛАВИАТУРА:

```
GLFW (SDL-нормализация)          core, чистая логика              логика игры
┌─────────────────────┐   ┌──────────────────────────────┐   ┌──────────────┐
│ GlfwPadPoller       │──>│ PadRouter                    │──>│ InputQueue   │
│ (lwjgl3-модуль):    │   │ (гистерезис стика, счётчик   │   │ (10 Гц тик)  │
│ опрос каждый кадр,  │   │ ссылок, releaseAll) + PadMap │   │      │       │
│ диф press/release   │   │ (кнопка -> gdx-код порта)    │   │      v       │
└─────────────────────┘   └──────────────────────────────┘   │ KeyMap -> J2 │
                                                             └──────────────┘
```

Сцены не знают о геймпаде: они по-прежнему читают `drainKeyDowns/Ups`
и переводят через `KeyMap`. Мост лишь вызывает `InputQueue.injectDown/Up`
с теми же кодами, что и клавиатура — путь, уже обкатанный автотестами
(`-Dhouse13.script`) и будущим тач-вводом Android.

## Маппинг (PadMap.DEFAULT — позиционная раскладка)

| Кнопка | gdx-код | J2ME (KeyMap) | Действие в игре |
|---|---|---|---|
| D-pad ↑↓←→ | UP/DOWN/LEFT/RIGHT | UP/DOWN/LEFT/RIGHT | движение руки, курсоры меню и сейф-клавиатуры |
| левый стик | — (синтез) | UP/DOWN/LEFT/RIGHT | то же, с гистерезисом (вкл 0.50 / выкл 0.35) |
| A (нижняя) | ENTER | FIRE | OK: выбор / действие / «дальше» / клетка сейф-клавиатуры |
| B (правая) | ESCAPE | SOFT_RIGHT | отмена / меню игры / пауза |
| X (левая) | Z | NUM_1 | инвентарь (карусель предметов) |
| START | F1 | SOFT_LEFT | меню/настройки (левый софт) |
| L2 или R2 (удерж.) | SHIFT_LEFT | isShift | ускорение руки x2 |
| Y, SELECT, L1, R1, L3, R3, GUIDE | — | — | резерв (см. «Полная реализация») |

Коды ENTER/ESCAPE/F1 — в точности коды токенов `F`/`Rs`/`Ls`
автотестов: геймпадные нажатия эквивалентны проверенным сценариям.

**Раскладка NINTENDO** (готова в коде, выбор — в настройках полной
реализации): своп A↔B и X↔Y по МЕТКАМ — OK на кнопке «A» Switch-пада.
SDL/GLFW нормализуют ПАДЫ ПОЗИЦИОННО (нижняя кнопка = A), как
Xbox/PS/Steam, поэтому DEFAULT совпадает с привычным поведением
большинства платформ.

## Гарантии PadRouter (все покрыты тестами)

- **Счётчик ссылок на клавишу**: D-pad + стик дают ОДНО нажатие UP;
  L2 + R2 делят один SHIFT; отпускание уходит только когда ушёл
  последний источник.
- **Гистерезис стика**: вкл при |v|≥0.50, выкл при |v|<0.35 — нет
  дребезга на границе мёртвой зоны; диагонали независимы по осям;
  разворот RIGHT→LEFT даёт оба события в одном тик-окне (down нового +
  up старого) — ровно как клавиатурный разворот стрелок.
- **releaseAll** при отключении пада и смене раскладки: ни одна
  клавиша не «залипает» (ускорение, защёлки направлений).
- Дубли press и «сиротские» up игнорируются; незмапленные кнопки
  физически трекаются (для будущего оверлея), но ничего не инъекцируют.

## Десктопный мост (GlfwPadPoller)

- `glfwGetGamepadState` — SDL Game Controller API внутри GLFW:
  единый позиционный лейаут + встроенная база маппингов гейпадов
  (Xbox/PS/Switch/generic). Внешних зависимостей нет.
- Опрос с дифом: poll() каждый кадр (60 Гц vsync) ДО логических
  тиков; события копятся в InputQueue и выравниваются с шагом 10 Гц.
  60 Гц сэмплирования против минимального тапа ~50 мс — потерь нет.
- Хотплаг: подключение/отключение опрашивается каждый кадр
  (jid 0..15); отключение → `padDisconnected()` → releaseAll.
- Триггеры L2/R2 — виртуальные кнопки с порогом 0.5 (гистерезис
  аналоговых осей — полная реализация).
- Активен первый найденный геймпад (несколько падов — полная реализация).

**Почему не gdx-controllers**: официальное расширение на Maven Central
(`com.badlogicgames.gdx:gdx-controllers*`) закончилось на 1.9.13 —
несовместимо с libGDX 1.14.x; новая линия публикуется через JitPack
(внешний репозиторий = риск сборки). GLFW-мост: ноль новых
зависимостей, вся SDL-нормализация бесплатно, весь тестопригодный
код — в core без GLFW вообще. Если расширение вернётся на Central —
мост заменяется без касания ядра (контракт PadPoller).

## Свойства запуска (десктоп)


## Полная реализация (список задач поверх фундамента)

1. **Android-мост** (этап 6): `InputDevice/MotionEvent` → `PadRouter`
   (контракт PadPoller уже готов); D-pad/ButtonKey от геймпада и
   GameTextInput не нужны — только игровые кнопки.
2. **Экран/секция настроек**: выбор раскладки DEFAULT/NINTENDO
   (`PadRouter.setMap` уже отпускает зажатое), чувствительность стика.
3. **Ремап кнопок**: PadMap уже инстанс с `isMapped/j2` — данных
   достаточно для UI пересборки; персист в Settings.
4. **Оверлей-индикатор**: `PadRouter.describe()` готова для отрисовки
   (имя пада + зажатое + стик); иконка «геймпад подключён» в углу.
5. **Резерв кнопок**: Y (карта дома?), SELECT (переключение перевода
   vpk/авторский — быстрая кнопка для сравнения), L1/R1 (листание
   страниц помощи/интро), правый стик (курсор для тач-сцен).
6. **Триггеры**: аналоговый гистерезис + калибровка нуля (для старых
   падов с ненулевым покоем).
7. **Вибрация** (rumble): callback через PadPoller, сцены не трогаем.
8. **Несколько падов**: активный игрок/переключение по GUIDE.

## Ограничения фундамента (осознанные)

- Разворот стика «в один тик» (down нового + up старого) даёт один
  «пустой» тик — ровно как клавиатура при быстрой смене стрелок;
  консистентность с клавиатурой важнее микромгновенного разворота.
- Мёртвая зона стика круговая не нужна: пороги по осям + гистерезис
  дают то же качество для 4-направленной J2ME-логики.
- GUIDE не перехватывается принципиально (системная кнопка).
